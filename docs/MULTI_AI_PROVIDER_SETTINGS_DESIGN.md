# 複数AIサービス設定画面の設計

## 基本方針
- 利用するAIサービスはGemini／Groq／Cloudflare Workers AIの3種類とする。
- 3サービスとも各社のAPIへ直接接続する。Cloudflare AI Gatewayは利用対象に含めない。
- メール抽出・マスキング・プロンプト生成・結果表示などの共通処理と、各AIプロバイダーの通信処理を分離する。
- APIキー・トークンはWindows DPAPIで保護してローカル保存する。ログ、診断情報、GitHubリポジトリには値を出さない。
- 学習利用の有無とデータ保持の有無を別項目として扱い、根拠が確認できない場合は「未確認」とする。
- 無料枠・残量・利用可能件数は、公式APIで取得できる値とローカル実績からの推定値を明確に区別する。
- 旧Gemini設定および既存のプロバイダー設定を移行時に失わない。

## 設定画面
タブは「AIサービス」「マスキング」「詳細」の3つに整理する。

### AIサービス
最初に使用するAIサービスを選択し、選択中のサービスに必要な設定だけを表示する。

| サービス | 接続情報 | モデル管理 |
|---|---|---|
| Gemini | APIキー | モデル選択、公式一覧更新、接続テスト |
| Groq | APIキー | モデル選択、公式一覧取得 |
| Cloudflare Workers AI | Account ID、API Token | モデル選択、公式一覧取得 |

サービスを切り替えても、各サービスのAPIキー・モデルIDは個別に保持する。モデル一覧はローカルにキャッシュし、起動時は保存済み一覧を表示する。手動入力したモデルIDも保持できる。

### マスキング
- メールアドレス、電話番号、郵便番号、IPアドレス、会社名、氏名、住所、口座・顧客・社員番号を個別に設定する。
- 追加登録語句を1行に1件ずつ管理する。
- マスキング設定はWindows DPAPIで暗号化して保存する。

### 詳細
- Geminiの一時エラー時のモデル自動切り替え
- Geminiモデル一覧更新時の有料・料金未確認モデルの扱い
- 詳細デバッグログ

## モデル品質・利用条件
- 公式APIのモデル一覧は利用可能性の情報であり、Free枠や品質を保証するものではない。
- モデルごとの品質評価は、実際の動作確認結果に基づくポリシーJSONから取得する。
- 未確認の仕様・コンテキスト長・利用枠は推測せず「未評価／未確認」とする。
- 学習利用の有無とデータ保持条件は分けて扱う。

## 内部構成
```text
メール処理・共通UI
       |
AI共通処理（マスキング／プロンプト／結果処理）
       |
プロバイダー選択
   /      |       \\
Gemini   Groq   Workers AI
  |       |        |
Google   Groq   Cloudflare
API      API    Workers AI API
```

- Gemini固有のJSON形式、モデル一覧、エラー処理、継続生成処理はGeminiアダプターに閉じ込める。
- GroqおよびWorkers AIは各社のOpenAI互換Chat Completions APIを利用する。
- プロバイダー固有の利用量・レート制限情報は取得元と単位を保持し、根拠なく共通の残量へ換算しない。

## 受け入れ条件
- 既存Gemini利用者は既存APIキー・モデル設定を維持して利用できる。
- 旧バージョンのGateway経路設定は直接接続へ正規化され、Gateway用資格情報は再利用されない。
- 選択したプロバイダーとモデルが各AI機能で一貫して使用される。
- 資格情報がログや送信プロンプトに含まれない。
- サービス切り替え後も別プロバイダーのモデルIDを誤用しない。
- Win32 Releaseビルド、CTest、Becky実機試験を通過する。
